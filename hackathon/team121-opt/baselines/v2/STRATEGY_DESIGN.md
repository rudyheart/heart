# v2.0 策略设计

## 决策流水线

```text
TurnState
  ├─ 解析己方/对手 Beam、地形、领地、轮廓和加速区
  ├─ 校验上一回合宏计划是否仍与实际位置/朝向一致
  ├─ 若己方在领地外
  │    ├─ 计算最短合法回家路线
  │    ├─ 基于对手真实回合可达图计算己方轮廓被切时间
  │    └─ 如果对手先到线，放弃扩张计划并回家
  ├─ 若己方在领地内且无己方轮廓
  │    ├─ 检查是否能在对手闭合前切断其轮廓
  │    ├─ 在领地内做带朝向 BFS，获得可达锚点
  │    ├─ 枚举 2/3/4 段正交闭合路径
  │    ├─ 根据 bbox 收益、长度和敌方到达时间初筛
  │    ├─ 用官方规则同构的边界 flood-fill 计算实际圈地集合
  │    ├─ 计算关键格面值、抢地收益和露边成本
  │    └─ 选择净收益/耗时最高的计划
  ├─ 对宏计划第一步做有限的一步引擎推演
  └─ 无可行计划时选择合法且尽量留在己方领地的方向
```

## 关键算法

### 1. 多形状闭合搜索

不是预设矩形宽高，而是从己方领地内可达锚点出发，枚举第一条出门线、第二条垂直线、第三条回切线；仍未进入己方领地时，再尝试第四条回边。路径必须满足：

- 不越界、不穿过 `#`、不踩任何已有轮廓；
- 不自交；
- 出门后只能在整条路线的最后重新进入己方领地；
- 每个动作均符合起步格加速和不可掉头规则；
- 一个加速动作的两步必须保持同一方向。

路径生成采用有限候选和软时间预算，避免在 200ms 回合约束下做无界搜索。

### 2. 精确圈地估值

将己方领地、己方旧轮廓和候选新轮廓作为 flood-fill 墙体，从棋盘边界做四邻接泛洪。不能从边界到达、且不是己方领地、校准区或缺陷的格子就是候选圈地集合。随后基于候选前后的局部边界变化，估算：

`净收益 = 己方新增面值 + 对手损失面值 - 己方露边扣分变化 + 对手露边扣分变化`

`*` 格按 3 分，其余可占格按 1 分。抢到对方领地同时增加己方分、降低对方分。

### 3. 敌方到达时间

在 `(x, y, heading)` 状态空间做 BFS，每个边代表一次裁判回合；每次扩展从当前格读取 `move_steps(x,y)`，而不是把所有格都假设为两步。首步不能反向，路径不能越界、撞缺陷或踩自己的旧轮廓。每个可达格记录最短回合数，用于衡量对手切断候选轮廓的窗口。

### 4. 动态防守与切线

在己方已有轮廓时，每回合重算对手到己方轮廓的 ETA。如果对手到线时间不大于己方最短回家时间加安全余量，立刻放弃原计划回家。

当己方没有开放轮廓、对手存在未闭合轮廓时，尝试搜索短路径切入对手线，并与对手最短回家时间比较。该攻击每回合重新评估，不持有长追击承诺。

## 与参考源码的关系

公开的 `chen-006/meow-ai-arena/land` 冠军 Sonnet 与亚军 GPT-6 Astra 源码均使用了多方向闭合搜索、精确区域填充和敌方到达时间估计。此工程重新实现了这些思想，没有直接复制其 C++ 实现；具体规则与评分以本赛题提供的规则摘要为准。

## 仍需真实引擎回归的风险

1. boost 双 substep 中，若第一步已闭合，第二步如何继续结算；
2. `calib`、`owner`、`contour` 的实际 SDK 数据结构；
3. 对手死亡冷却中的坐标和 `restart_in` 更新时序；
4. `game.copy().step()` 的执行耗时；
5. 真实地图上多形状路线的收益分布和被切线率。
