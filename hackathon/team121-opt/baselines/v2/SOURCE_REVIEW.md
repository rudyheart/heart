# 参考项目源码分析：AI 算法对抗大赛 · 第 1 期「圈地」

参考网页：<https://arena.meowllm.top/ep1/>
公开仓库：<https://github.com/chen-006/meow-ai-arena/tree/main/land>

## 结论：核心玩法相似，但不能直接移植

两者都是从自家领地出发、在领地外留下轨迹、返回自家领地后通过 flood-fill 圈地，并且开放轨迹会被对手切断。但规则层有本质差异：

| 项目 | 第 1 期「圈地」 | 2026「曝光领地」 |
|---|---|---|
| 棋盘 | 1v1 为 40×40；混战为 48×48 | 41×41 |
| 玩家数 | 2 或 4 | 2 |
| 地形 | 无缺陷障碍 | `#` 不可通行 |
| 速度 | 每回合 1 格 | 普通 1 格；从加速区起步 2 格 |
| 地块分值 | 占领格数 | `.`=1，`*`=3 |
| 计分 | 领地总格数 | 面值总和减露边扣分 |
| 死亡 | 清轨迹并立即传回出生点 | 清轮廓、离场冷却 5 回合后重启 |
| 回合 | 600 | 600 |
| 通信 | stdin/stdout 文本行，单步 50ms | Python SDK / HTTP，单回合 200ms（以参赛指南为准） |

因此，不能把参考项目的 C++ bot 直接作为你们的 Bot：通信协议、棋盘、地形、移动和计分都不同。

## 看了哪些源码

- `land/workspace/engine/game.py`：权威逐回合规则，重点看 `Game.step()`、`_enclosed()`。
- `land/workspace/RULES.md`：完整动作时序、轨迹切断、碰撞、同时圈地和协议。
- `land/bots/sonnet-5@claude-code#1/bot.cpp`：公开赛冠军源码。
- `land/bots/gpt-6-astra@codex#1/bot.cpp`：公开赛亚军源码。
- `land/bots/opus-5.5@claude-code#1/bot.cpp`：另一套安全闭合与追击策略。

## 冠军 Sonnet 的主要思路

1. **精确 flood-fill 估值**：模拟轨迹闭合后的真实区域，而不是只按矩形面积估值；实现上用按行 bitset 做快速泛洪。
2. **安全路径筛选**：对每个对手做路径距离 BFS，计算敌方到候选轨迹的最短回合数；完成圈地需要的回合数若太长，就不执行。
3. **多折线候选**：枚举两段和三段路线，先用便宜的包围盒收益排序，再对高分候选做精确区域估值。
4. **随机局部改良**：从较好的路线出发，随机微调每一段长度，在有限计算预算内寻找更高的收益/耗时比。
5. **切线攻击**：对手有开放轨迹时，评估能否在对手回家前抵达并切断；若自身线路风险过高则不追。
6. **提前回家**：当前路线边际安全不足时，比较继续扩张与立即回家的收益，及时缩短暴露时间。

## Astra 的主要思路

1. 使用 `(位置, 朝向)` 的状态做领地内 BFS，生成多个不同锚点和方向。
2. 同时搜索矩形、桥接/连接类候选，不只依赖一个几何模式。
3. 按“回合”计算敌方可达距离，并考虑敌方开放轨迹回家时间。
4. 使用 receding-horizon 方式逐回合复核当前计划，必要时重规划或改走更短的返回线。
5. 对多玩家情况下的对手威胁赋权；本赛题是双人，不需要照搬它的多玩家排名模型。

## 对 team121 v2.0 的具体落地

| 参考思想 | v2.0 的适配实现 |
|---|---|
| 多折线路线搜索 | `_build_loop_candidates()` 搜索 2/3/4 段路径，不强制完整矩形底边 |
| 精确 flood-fill | `_compute_capture_set()` 以己方领地、旧轮廓和新轮廓为墙，从棋盘边界泛洪 |
| 基于回合的敌方 ETA | `_enemy_turn_distance_map()` 使用朝向状态和起步格 `move_steps()`，不再全图距离除以 2 |
| 提前回家 | `Strategy.act()` 每回合比较敌方抵达己方轮廓 ETA 与回家路径长度 |
| 切线攻击 | `_find_enemy_cut_route()` + `_enemy_return_turns()` 尝试短时截断 |
| 本题不同的得分 | `_score_delta_for_capture()` 保留关键格 3 分和双方露边扣分 |

## 不能从参考项目照搬的部分

- 参考 bot 的 `exactGain()` 按普通领地格估值；本题需要 1/3 面值与边缘罚分。
- 参考 bot 的所有直线都按每回合一格模拟；本题路径必须遵守 boost 从起步格判定的双步规则。
- 参考 bot 把碰撞/死亡直接传回出生点；本题存在 5 回合冷却和重启时序。
- 参考 bot 的 C++ stdin/stdout 协议不能代替本题 Python SDK / HTTP 服务。
