# 官方引擎与旧策略审计

核对材料来自 Madelining/heart 比赛分支，包括 player-kit/engine/game.py、maps.py、rules.py、protocol.py、match.py、replay.py、赛题规则、Python 模板及 bot001/002/003。引擎批次为 1a33854。rudyheart/heart 原始策略基点为 72d35b7。

| 项目 | 源码实际行为及策略影响 |
|---|---|
| 地图 | 41×41，600 回合。地图由独立种子生成，生成器有 open/walls/lanes/blocks/mixed 五种布局，地形中心对称且可通行区连通。出生点随地图变化，两个校准区固定归属。 |
| 计分 | 校准区九格计面值，开局 9 比 9，只豁免校准区自身露边。全盘普通格值 1，星格值 3，减各自总露边数整除 3。一格被抢占会改变双方分数。 |
| 起步与加速 | 起步格在任一加速区覆盖集合中则沿同一方向尝试两格，否则一格。反向回复合法且不改变朝向。 |
| 碰撞 | 每子步先判缺陷和越界。仅双方该子步都在移动时判断同格或交换位置；目标在己方领地的移动者存活。快方第二步可以进入已停下的对手所在格，仍需判轮廓。 |
| 轮廓 | 双方同时按该子步开始时的轮廓判定切线。自踩使自己报废，踩对方使对方报废。报废者不再延伸、闭合或走剩余子步。 |
| 闭合 | 每子步先延伸后算闭合，己方领地、己方轮廓是墙。外沿四邻接泛洪可以穿过缺陷；缺陷和校准区不进入新获格。两方同时闭合时共同候选保留原归属。加速第一步闭合后，第二步可以开始新轮廓。 |
| 重启 | 回合末清报废方轮廓，保留领地。此后第 5 个停机回合末在出生点复活，可能踩断对方线，最后补标在场束斑。 |
| 裁判 | 终局按得分、严格领先回合数、较短累计请求耗时三层比较。三项完全相同待裁定。程序退出技术判负；超时、连接、非法回复累计达 10 次判负。同一轮两方均触发则双败。 |
| SDK 协议 | 地图启动传送。每回合号从 1 开始，owner/contour 行字符串为 ./0/1，score 以席位排列；响应必须是同一整数回合和一字符方向。GET health 10s，init 2s，turn 请求往返 200ms，end 1s。 |

旧 v2 将缺陷当作泛洪墙，局部露边先取整、漏掉既有全局余数；计算敌方可达图后才启动部分搜索期限；回不到家时同回合可重复做 BFS；模拟全部报错时默认五种回复均存活。其完整 47,654 字节 strategy.py 和八个分片文件由 ZIP 长度及 CRC32 核对。命令 `python tools/verify_recovered.py` 可逐字节验证原件。主策略 SHA-256 为 620d7e70e431256d37255a3ed3b70bcfcc034df2ca5a72bc8498449045e0ae7f。
